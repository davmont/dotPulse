# dotPulse 3.3.2 Release Notes

**Release date:** 2026-11-22

dotPulse 3.3.2 is a **security release** for sites that use **LDAP login**. With the setting **LDAP also allows standard login** on (the default), someone disabled in the directory, or whose directory password had changed, could still log in to dotPulse with the password they had at their first LDAP login. **Upgrade every installation of 3.3.1 or earlier that uses LDAP login.** Sites that log in with dotPulse passwords (the default method) are not affected. See advisory [GHSA-9pj7-2prh-h68c](https://github.com/davmont/dotPulse/security/advisories/GHSA-9pj7-2prh-h68c).

It upgrades 3.3.1 in place, with no database changes.

---

## Security

- **LDAP login accepted an old password** (medium). dotPulse keeps a copy of the password of users created at their first LDAP login. It tried that copy before the directory, and never updated it. Now the directory decides for the people it has, and the copy is updated at each login. The dotPulse password is used only for accounts the directory doesn't have (such as `admin`), and while the directory can't be reached.
- The login name is escaped in the LDAP search filter. A name with `*` or `)(` changed the search; this did not let anyone log in, but searches are now exact.

## Upgrading

1. **Back up** the database and the `files/` directory.
2. **Replace the code.** Keep `includes/config.php` and `files/`.
3. **Run the installer** (`install/` in a browser) to record the new version. There are no database changes. Then remove `install/` again or deny access to it.
4. If you use LDAP: people log in with their **directory** password from now on, even if their old dotPulse password still matched. Remove the roles of people who left: while the directory can't be reached, their last password still works.

From a version older than 3.3.1, read [the 3.3.1 release notes](v3.3.1.md) first.

# dotPulse 3.3.0 Release Notes

**Release date:** 2026-11-20

dotPulse 3.3.0 is about working in the charts and the calendar, and about everything the documentation review turned up:
- drag task bars in the Gantt charts to change dates and progress, with Esc to cancel and Undo;
- the calendar shows the holidays of each user's workplace;
- Help shows the documentation for the page you are on, inside dotPulse;
- users can edit their own name, e-mail and signature;
- about 40 bugs found while writing the documentation website, and the ones a full static analysis of the core found, are fixed.

It upgrades 3.2.x in place: replace the code, run the installer to record the version, and upgrade five add-on modules in System Admin > Modules if you use them. Read **Changes to know about** first.

---

## Changes to know about

- **Five add-ons stored text as Latin-1** (annotations, finances, opportunities, macroprojects, testing): text outside Latin-1 (`日本`, `č`) was saved as `?` with no error. Their new versions convert the tables to utf8mb4. **Upgrade them in System Admin > Modules** (annotations 0.2.8, finances 1.2, opportunities 0.1.4, macroprojects 1.1, testing 1.0.2). Nothing that was stored is lost; text already saved as `?` stays that way.
- **Help reads the documentation shipped with the code** (`website/docs`). Deploy the `website/` directory with the rest of the code. `$dPconfig['help_url']` still points the help links at another copy of the documentation if you set it.
- **`vendor/` has a new package** (Parsedown 1.8, for Help) and PHPMailer 7.2.0. Replace `vendor/` with the code.
- **Translation page:** saving a page writes untouched entries back exactly as they were, and keeps their "machine translated" (`// MT`) mark, so a language can be reviewed in parts. If you edited translations, keep a copy of `locales/` and `modules/*/locales/` before replacing the code, as always.
- **The installer offers MySQL/MariaDB (mysqli) only.** The other database types never worked.
- **The project page opens on the user's last tab** (or the first one). It used to open on **Tasks (Inactive)**.
- **Deleting a project deletes its task logs** with its tasks; they were left behind as orphans. The confirmation says so.

## New

- **Gantt: drag to edit.** On task charts (project tab, tasks, to-do, the projects chart's task bars and Project Designer), a user who may edit a task can drag its bar to move it, drag an end to change its start or last day, and drag the progress handle. Esc while dragging cancels; after a saved change, **Undo** puts it back. Task groups, read-only charts and project bars refuse with a message. The interactive Gantt add-on (igantt) uses the same chart and the same rules, and shows only the tasks the user may see.
- **Holidays in the calendar** (with the holiday module): the month, week and day views and the small calendars shade the holidays of the user's workplace and name them.
- **Help for the page you are on.** The header's Help shows the matching page of the documentation (projects, tasks, Gantt, calendar, files, your account, administration…), inside dotPulse and for the installed version. Old `?m=help&hid=…` links still work.
- **Edit your own account.** Every user can change their name, e-mail, e-mail signature and password on My Info. Changing the e-mail or the password asks for the current password. Login name, user type, role, company and department stay with user administrators.
- **Default admin password warning:** System Admin shows an Attention tile while the `admin` account still has the installer's password.
- **Dark theme:** the date picker and tooltips are dark too, and the theme was checked on every page of the application. **Light theme:** Gantt bar labels and System Admin's input and button edges have readable contrast.
- **Vector icons** for the bitmaps that were left: help desk call types, annotations, the files module's navigation, the task assignment buttons, Project Designer, and all 253 file-type icons.
- **Documentation website:** www.dotpulse.org, with Getting started and the user guide (CC BY-SA 4.0; code examples under the GPL).

## Fixes

- **Projects and tasks:**
  - the project's **Tasks (Inactive)** tab listed the active tasks in any language but English;
  - the Gantt charts' **show this month** filtered nothing; task bars on the projects Gantt always showed 0 %;
  - "All Tasks I Have Created" listed tasks you own;
  - ticking **Milestone** sets the finish date to the start date;
  - reopening a closed task left its subtasks closed;
  - the task list report sorted by project start only;
  - the task logs report gave a fatal error instead of "access denied";
  - the Dates tab showed working days shifted by one and double-encoded.
- **Smart search:** keywords with `(`, `c++` or `a.b` gave SQL errors; **Ignore special chars** never worked; a project with several contacts was listed once per contact.
- **Forums:** "(moderated)" showed on every forum; the edit and delete icons follow the save rules.
- **Files:**
  - a file marked final refused its project owner and administrators;
  - replacing a file whose old copy could not be deleted now warns;
  - the e-mail notifications said "File x was  by";
  - a failed save of a file record went unreported.
- **Contacts:** the list showed Edit to users who may not edit; the projects count used an old column; vCard import and export swapped the type and middle name.
- **Calendar:** task finish marks appeared outside the period; the clash page had a fatal error when opened without an event.
- **Translation page:** it did not open for most languages on PHP 8 (a fatal error on long texts), and for seven modules it saved over the wrong file, replacing the module's core translations (for example, saving French Projects replaced 311 entries with 79).
- **Add-ons:** fatal errors in dataimport and timesheet; mileagelog's settings were all off; the journal's project filter, informer's monthly hours, invoices' cost codes and the reports, testing and helpdesk modules each had a bug, now fixed. Forms that overflowed at 1024 px fit.
- Billing codes: updating one could fail without a message.

## Security and hardening

- **Request input:** the core reads all request input through the validating helpers (`dPgetParam()`, `dPgetIntParam()`); what is left is in add-on modules, converted when they are needed.
  - A `csrf_token` sent as an array caused an error page instead of the usual refusal.
  - The installer accepts only "install" or "upgrade" as its mode.
- **Static analysis:** PHPStan's list of known findings is down from 659 to 213 (63 in the core). Its list had grown stale; it is now regenerated and kept exact.
  - Fixed: undefined constants and functions that were fatal errors on PHP 8 (files, smart search, ticketsmith, query class).
  - Removed:
    - `CForum::search()`: unused, with unescaped SQL;
    - `install/docs/check.php`: a 2006 diagnostics page, not reachable once installed;
    - `modules/ticketsmith/login.php`: a page that always failed.
- **The mngdocument add-on:** its file class is `CMngDocumentFile`, so it no longer clashes with the core files module.
- **Development tools:** `make deps-audit` skips a picomatch advisory (GHSA-fc5q-39xc-vjpf) that has no fixed release; picomatch is used only by the Jest tests, never deployed.

## Translations

- New strings are in all 25 languages: English and Spanish by hand, the others machine translated and marked `// MT`.
- Known wrong terms were corrected in French, Swedish, Turkish, Catalan, Korean, Danish, Chinese, Dutch, Norwegian and Slovenian.

## Upgrading

1. **Back up** the database, the `files/` directory and, if you edited translations, `locales/` and `modules/*/locales/`.
2. **Replace the code**, including `vendor/` and `website/`. Keep `includes/config.php` and `files/`. Delete the old tree rather than copying over it, so that removed files do not stay behind (`install/docs/check.php`, `modules/ticketsmith/login.php`, the old help files in `modules/help/`, `modules/igantt/update_task_dates.php`, `modules/files/tasks_tab.files.php`).
3. **Upgrade the add-ons** you use among annotations, finances, opportunities, macroprojects and testing in System Admin > Modules.
4. **Run the installer** (`install/` in a browser) to record the new version. There are no core database changes. Then remove `install/` again or deny access to it.

From 3.1.x, read [the 3.2.0 release notes](v3.2.0.md) first (PHP 8.2 or later, holiday module upgrade).

## Requirements

- PHP 8.2 or later (8.3 is tested), MySQL or MariaDB.
- Apache (recommended) or nginx with the rules from the deployment guide.
